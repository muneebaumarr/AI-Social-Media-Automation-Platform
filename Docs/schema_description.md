# Relational Database Schema Description

## Project Title
AI Social Media Automation Platform

## Project Overview
The AI Social Media Automation Platform is a database-based system that helps users create, manage, approve, schedule, and track social media posts. The system also stores AI-generated captions and content history.

---

## 1. USERS Table

### Purpose
The USERS table stores information about all users of the system, such as admins, managers, and content creators.

### Attributes

| Attribute | Data Type | Key | Description |
|---|---|---|---|
| user_id | INT | Primary Key | Unique ID for each user |
| full_name | VARCHAR(100) |  | Full name of the user |
| email | VARCHAR(100) | Unique | Email address of the user |
| password | VARCHAR(255) |  | Password of the user |
| role | VARCHAR(50) |  | Role of the user, such as admin or content_creator |
| created_at | DATETIME |  | Date and time when user account was created |

### Relationships
- One user can create many posts.
- One admin user can approve many approval records.

---

## 2. POSTS Table

### Purpose
The POSTS table stores social media post details created by users.

### Attributes

| Attribute | Data Type | Key | Description |
|---|---|---|---|
| post_id | INT | Primary Key | Unique ID for each post |
| user_id | INT | Foreign Key | References user_id in USERS table |
| title | VARCHAR(150) |  | Title of the post |
| content | TEXT |  | Main content of the post |
| ai_caption | TEXT |  | AI-generated caption for the post |
| status | VARCHAR(50) |  | Current status of post, such as draft, pending, approved, rejected, or scheduled |
| created_at | DATETIME |  | Date and time when post was created |

### Relationships
- Many posts can belong to one user.
- One post can have many approval records.
- One post can have one scheduled post record.
- One post can have many analytics logs.
- One post can have many AI generation records.

---

## 3. APPROVALS Table

### Purpose
The APPROVALS table stores approval information for posts.

### Attributes

| Attribute | Data Type | Key | Description |
|---|---|---|---|
| approval_id | INT | Primary Key | Unique ID for each approval record |
| post_id | INT | Foreign Key | References post_id in POSTS table |
| approved_by | INT | Foreign Key | References user_id in USERS table |
| approval_status | VARCHAR(50) |  | Approval status, such as approved or rejected |
| approval_date | DATETIME |  | Date and time when approval action was taken |

### Relationships
- Many approval records can belong to one post.
- Many approval records can be approved by one user/admin.

---

## 4. SCHEDULED_POSTS Table

### Purpose
The SCHEDULED_POSTS table stores scheduling information for approved posts.

### Attributes

| Attribute | Data Type | Key | Description |
|---|---|---|---|
| schedule_id | INT | Primary Key | Unique ID for each scheduled post |
| post_id | INT | Foreign Key | References post_id in POSTS table |
| scheduled_time | DATETIME |  | Date and time when the post is scheduled |
| platform | VARCHAR(50) |  | Social media platform such as Facebook, Instagram, LinkedIn, or Twitter/X |

### Relationships
- One post can have one scheduled post record.
- Each scheduled post belongs to one post.

---

## 5. ANALYTICS_LOGS Table

### Purpose
The ANALYTICS_LOGS table stores performance data of social media posts.

### Attributes

| Attribute | Data Type | Key | Description |
|---|---|---|---|
| analytics_id | INT | Primary Key | Unique ID for each analytics record |
| post_id | INT | Foreign Key | References post_id in POSTS table |
| views | INT |  | Number of views on the post |
| likes | INT |  | Number of likes on the post |
| comments | INT |  | Number of comments on the post |
| shares | INT |  | Number of shares on the post |
| recorded_at | DATETIME |  | Date and time when analytics were recorded |

### Relationships
- One post can have many analytics log records.
- Each analytics log belongs to one post.

---

## 6. AI_GENERATIONS Table

### Purpose
The AI_GENERATIONS table stores AI-generated content history for posts.

### Attributes

| Attribute | Data Type | Key | Description |
|---|---|---|---|
| generation_id | INT | Primary Key | Unique ID for each AI generation record |
| post_id | INT | Foreign Key | References post_id in POSTS table |
| prompt | TEXT |  | Prompt entered by the user |
| generated_text | TEXT |  | Text generated by AI |
| generated_at | DATETIME |  | Date and time when AI content was generated |

### Relationships
- One post can have many AI generation records.
- Each AI generation record belongs to one post.

---

# Relationship Summary

| Relationship | Type | Description |
|---|---|---|
| USERS to POSTS | One-to-Many | One user can create many posts |
| POSTS to APPROVALS | One-to-Many | One post can have many approval records |
| USERS to APPROVALS | One-to-Many | One admin user can approve many posts |
| POSTS to SCHEDULED_POSTS | One-to-One | One post can have one schedule record |
| POSTS to ANALYTICS_LOGS | One-to-Many | One post can have many analytics records |
| POSTS to AI_GENERATIONS | One-to-Many | One post can have many AI-generated content records |

---

# Primary Keys

| Table | Primary Key |
|---|---|
| USERS | user_id |
| POSTS | post_id |
| APPROVALS | approval_id |
| SCHEDULED_POSTS | schedule_id |
| ANALYTICS_LOGS | analytics_id |
| AI_GENERATIONS | generation_id |

---

# Foreign Keys

| Table | Foreign Key | References |
|---|---|---|
| POSTS | user_id | USERS(user_id) |
| APPROVALS | post_id | POSTS(post_id) |
| APPROVALS | approved_by | USERS(user_id) |
| SCHEDULED_POSTS | post_id | POSTS(post_id) |
| ANALYTICS_LOGS | post_id | POSTS(post_id) |
| AI_GENERATIONS | post_id | POSTS(post_id) |

---

# Assumptions and Constraints

- Each user has a unique email address.
- A user can create multiple posts.
- Each post belongs to only one user.
- Only admin users can approve or reject posts.
- A post can have multiple approval records.
- A post can be scheduled only after approval.
- A scheduled post belongs to only one post.
- A post can have multiple analytics records over time.
- A post can have multiple AI-generated versions.
